# Проверка упрощения схемы

Из каталога API:

```powershell
dotnet run --project Scripts/Validation/SchemaChecks.csproj -- test
dotnet run --project Scripts/Validation/SchemaChecks.csproj -- inspect
dotnet run --project Scripts/Validation/SchemaChecks.csproj -- apply
```

Используется подключение `DefaultConnection` из `appsettings.json` или переменная
`ConnectionStrings__DefaultConnection`. Пароль не выводится в консоль.

`test` создаёт изолированную схему со случайным именем и удаляет её в `finally`.
Проверяет обновление предыдущей схемы с данными, соответствие снимка EF-модели,
повторное заполнение справочников, прогресс разных сохранений, покупки,
расстановку с родителем, расход инвентаря и откат с повторным применением.
Также проверяет стартовый набор: девять типов и девять экземпляров, бесплатную
выдачу, отсутствие повторного начисления и полного сохранения при неполном каталоге,
откат сохранения, прогресса и инвентаря при ошибке записи стартовой мебели.
`RewardChecks` проверяет выдачу новых ящиков по всем рецептам уровня,
исключение ингредиентов из ранее открытых рецептов, отсутствие выдачи при
непрохождении, повторном и одновременном завершении, уже купленный ящик,
последний уровень и атомарность при отсутствии ящика или ошибке записи.

`ResetSaveChecks` проверяет `POST /save/{save_id}/reset` с телом `{ "user_id": 123 }`.
Сброс удаляет сохранение, прогресс, инвентарь, расстановку и квитанции покупок,
сохраняя аккаунт. Новое сохранение не создаётся: после сброса вход возвращает
`save_not_found`, а обычный `POST /save` создаёт его после выбора персонажа.
Проверяются отказ для чужого сохранения, откат при ошибке удаления и безопасный
повтор старого запроса, в том числе после создания нового сохранения.

`inspect` только выводит известные, применённые и ожидающие миграции.

`CoveringChecks` входит в `test`: бесплатная покупка новых покрытий,
независимое применение пола и обоев, сохранение второго покрытия,
проверка владения и категории, неизменность количества и восстановление выбора.
PUT `/save/{id}/coverings` принимает `floor_id`, `wallpaper_id` либо оба поля.
Нужен хотя бы один положительный ID. Уже используемое базовое покрытие
можно оставить без отдельной записи владения в инвентаре.
`seed-coverings` добавляет два тестовых покрытия в рабочий каталог после
резервного копирования каталога (без изменений сохранений игроков).

`apply` изменяет рабочую БД. Допускает только новую миграцию
`20261109160000_AddDesserts`, предварительно создаёт полный дамп в `.backups`
через PostgreSQL 18 `pg_dump`. Проверяет сохранность количества строк и чтение
существующих сохранений. Если миграция уже применена, ничего не меняет.

Удалены `LevelProgresses.attempts_count`, `LevelProgresses.completed_at`,
`Recipes.quantity`, `Furnitures.is_consumable`, `Furnitures.is_available`,
`PlacedItems.rotation`, `PlacedItems.placement_layer`. Старые миграции сохранены.
Откат возвращает колонки с начальными значениями; прежние значения есть в дампе.

В API старта уровня осталась проверка доступности без записи попытки. Рецепт
задаёт одну единицу каждого ингредиента. Количество мебели в инвентаре и покупке
сохранено. Доступность покупки определяется прогрессом выбранного сохранения;
расходуемость определяет игровая логика. API запрещает уменьшать количество ниже
числа размещённых экземпляров и расходовать последнее используемое покрытие.

Слой остаётся в справочнике `Furnitures.placement_layer`: `Floor`, `Wall`, `Table`.
GET и PUT расстановки возвращают его как `items[].item.placement_layer`.
PUT больше не принимает слой и поворот; положение экземпляра задают координаты
и `parent_client_id`, который преобразуется в `parent_placed_item_id` при сохранении.


Проверки сладостей также входят в `test`: 4 вида, цена 10 за партию из 3 штук,
продажа по 6 за штуку, отказ при нехватке денег, повтор квитанции без второго
списания, конфликт квитанции и одновременные покупки (включая покупку мебели).
